# Dogfooding robostickies exposed interface defects

Using the installed CLI and the agent's actual MCP connection while developing robostickies helped identify problems in the interface:

- Read tools silently accepted unsupported arguments. Strict validation now rejects unknown fields before execution ([fix](https://github.com/canardleteer/robostickies/commit/fe1f029b3f62cfaa5299a83a95c164fe2de5c40d)).
- Review advertised pagination even though it returned complete results. CLI and MCP review now accept filters without paging inputs ([fix](https://github.com/canardleteer/robostickies/commit/450d3a795daeba79f62ff85d98d938101f70c8a6)).
- Local context did not identify the repository selected by the running server. It now reports the canonical startup root locally and omits it from public context ([fix](https://github.com/canardleteer/robostickies/commit/450d3a795daeba79f62ff85d98d938101f70c8a6)).

Follow-up code review and isolated reproductions found duplicate-ID selection problems and ineffective subprocess timeouts. Shared-editing changes also made revisions mandatory. After installation and agent restart, races through the actual MCP connection and CLI produced one successful edit and conflicts for stale writers, preserving the winning changes ([fix and regression tests](https://github.com/canardleteer/robostickies/commit/9b22f032fd9728ef038a5ba34522de5cf94edf24)).

Reuse this approach for interface and persistence changes: call `get_context`, exercise realistic workflows through the installed service, record expected and observed behavior, and turn reproducible defects into permanent Rust tests. Verify MCP fixes through the actual connection after installation and a user-confirmed restart. Keep raw test evidence private and delete synthetic fixtures before committing.

This paperclip records a reusable finding selected for public history. Its private source and run records remain local.
